# Changelog

All notable changes to TeXLib are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions correspond to git tags.

## [Unreleased]

### Changed

- **CI validates against TeX Live 2026 at last.** Issue #69 closed on 2026-08-17 with both tagpdf 1.0c incompatibilities fixed and the accessible suite green on TL2025 *and* TL2026 — but its second done-when clause, moving the container pin forward, never happened. All four workflows kept `texlive-full:20260101` (TeX Live 2025), so every accessible build merged since was being validated against last year's tagging engine, and the workflow comments still warned "do not bump" about an incompatibility that no longer exists. The pin is now `texlive-full:20260701` (TeX Live 2026) in `tests.yml`, `smoke.yml`, `visual.yml`, and `accessible.yml`; the stale warnings are rewritten; and the visual reference images are regenerated inside the new container via the `update_refs` dispatch, so refs and checks share one toolchain again.

- **An accessible build no longer stacks a second `\DocumentMetadata` on a document that declares its own.** The TeX Live 2026 kernel makes a duplicate declaration a fatal error (`Two \DocumentMetadata declarations`) where 2025 quietly ignored the second — so the thesis template, whose documented layout opens with its own declaration because the PDF/A + PDF/UA choices there are the author's to make, died on the spot in every accessible build under the new pin (the one failure in the first TL2026 CI run, 35/36). `accessible_macro_for` in `texlib_buildspec.py` now reads the document: a source carrying its own uncommented `\DocumentMetadata` receives only the `\TeXLibAccessibleMode` marker, everything else keeps the full injected prefix, and all three consumers (the Sublime builder, `smoke_test.py`, `gallery_harness.py`) go through it. Four new builder-suite checks pin the behavior, commented-out declarations included.

- **Everything that decides a gate's outcome is now version-pinned, not just the container.** The image pin never froze the tools layered on top of it: `apk add` resolves against Alpine's *live* v3.24 index (which is exactly how ImageMagick rolled to the 7.1.2.27 Beta under a pinned image on 2026-07-29 and cost the visual gate its fuzz tolerance), the veraPDF install pulled `/releases/verapdf-installer.zip` — a rolling "latest" whose upgrade would change PDF/UA conformance verdicts with no commit here — and pypdf floated on PyPI. Now: `imagemagick=7.1.2.27-r0` and `poppler-utils=25.12.0-r1` are pinned wherever they're installed (a version Alpine drops fails loudly at `apk add` instead of drifting silently); veraPDF is the versioned 1.30.2 installer, SHA-256-verified before it runs and version-asserted after it installs; and `pypdf==6.16.2` everywhere. The visual gate additionally logs `magick --version` and `pdftoppm -v` per run, the accessible.yml convention, so a disputed diff starts from a known renderer.

## [0.7.2] — 2026-08-25

A one-fix release: the accessible schedule no longer looks like a draft. The
box-grid renderer that every tagged schedule build rides on now reproduces the
tabularray calendar's geometry instead of approximating it.

### Fixed

- **The box-grid schedule finally looks like the schedule.** The box-grid renderer — the one every accessible schedule build is forced onto, since the tabularray calendar cannot be tagged — promised "the same visual grid" and never delivered it: rows floated apart with dead space between them, a cell whose date is `\fbox`'d (month starts) rode ~3.4pt above its neighbours, the `[c]`-centred week label sat below both, a divider stub poked above the header row, and every row overran `\textwidth` by ~20pt because the column-width formula ignored `\fboxsep`. All of it was one mistake: row components met the row `\hbox` on raw minipage baselines, and a `[t][h][*]` minipage's baseline sits at its *first line*, so any first-line difference moved the whole frame. Every component now passes through `\sched@topalign`, which re-baselines its frame to a uniform profile (height = the full frame, depth = 0) so content cannot move it; `\SchedSetCols` accounts for the `\fcolorbox` padding it had ignored; the framed-strut divider (a fat white channel — `\fboxsep` padding around a 1pt rule) is replaced by a bare `\scheddividergap` kern, so the WEEK‖days double rule is the label's right border and the first cell's left border; rows overlap their horizontal borders by `\fboxrule` (the vertical twin of the inter-cell kern, emitted on the row's own grid line so the `.schedmap` contract is untouched); and the header row gained the xltabular double-rule separator and a full-size WEEK (the label column widened 3.2em → 3.7em to fit it). Math 126's accessible schedule drops from 3 pages back to the normal build's 2 and still passes veraPDF ua-2; the five `schedule__box-grid-*.png` refs are regenerated, and every other scenario passes unchanged against its committed refs. The one remaining visible difference from the tabularray render is the documented tradeoff: a continuous grid still shows the day-name header only on its first page.

## [0.7.1] — 2026-08-24

A first-week follow-up to the pre-semester release. The published coded copy now
carries the Math & Stat Office submission name; exam dates print a weekday and a
full month; the schedule actually publishes rather than merely claiming to; an
accessible Notes build with gated solutions no longer dies at `\end{document}`;
and accessible mode is at last reachable from the build picker.

### Changed

- **The published coded copy now carries the Math & Stat Office submission name.** The department has asked since August 2025 for `MATH XXX.YYYY_<Term>_InstructorLastName`, and the reminder of 2026-08-20 restated it; the builder was emitting `Math181.1001_Fall2026.pdf`, so every submission needed a hand-rename first. `_coded_basename` now upper-cases the subject, **keeps** the single spaces the convention is written with (only runs are collapsed — they are legal in a filename everywhere TeXLib builds), and appends the instructor's last name, giving `MATH 181.1001_Fall 2026_Fox.pdf` straight out of the build. `STAT` courses and lettered numbers (`126EE`) take the same shape. Any segment whose coursemeta field is unset drops out rather than leaving a `__` gap, and `publish-name` still overrides the whole basename for a course this cannot express. The sidecar gained `instructor=` to carry the resolved field; the surname is the last token after a comma-tail and any generational/degree suffix are dropped (`Fox, Landon`, `Landon Fox, Ph.D.`, `Dr. Landon Fox` → `Fox`), with a multi-token surname left to the override rather than guessed at.

- **Exam dates read "Tuesday, December 15, 2026" — the weekday, and the month spelled out.** `final-date` is stored as `M-D` so the schedule's date math can parse it, and `\MetaHumanMonthDay` humanized it to `Dec 15, 2026` — a visibly different style from the free-form `exam<N>-date` rows sitting directly above it in the same table, which courses transcribe off the schedule as `Friday, December 4, 2026`. One table, two date formats, for a reason no reader could see. The month table now spells the names out and a weekday is prepended, so every row of `\examdatetable` and the autoexam Final-exam cover read alike whichever key fed them.

  The weekday is Zeller's congruence evaluated in expl3 — no date package and no `\directlua`, because `course-metadata.sty` is loaded by *every* class and half of them run pdflatex. January and February count as months 13 and 14 of the *previous* year; the month term and all four year terms take that shift through `\__meta_zyear:nn`. Checked against the calendar for every day from 2020 through 2035 — no mismatches.

  Only `M-D` values move. A key already written free-form (`August 12, 2026`) has no `-` to split on and is returned unchanged, which is what lets a course store either form. No reference images move: the module tier (18/18) and all 33 scenario packs (`--full`) pass unchanged against the committed refs.

### Added

- **`\examdatetable` prints the final exam's time.** When `final-time` is set it is stacked under the date in the Final Exam row (`\makecell`, so the Date column does not stretch to fit a date and a time side by side — no unit-exam row has a time to put beside it). UAM 3,517 pins the final to its Final Week grid slot, which is generally neither the course's meeting time nor anything students can infer from the meeting pattern, so a syllabus that prints only the date leaves out the half students actually ask about. `final-time` unset renders exactly as before, date alone. No reference images move: neither the Syllabi template nor any `syllabi__*` scenario calls `\examdatetable`, and module + all four scenarios pass unchanged.

- **`schedule.cls` actually opts in to the publish step.** The class never called `\TeXLibDeclarePublishable`, so `Tentative Schedule.pdf` — named in the builder, in `package_for_lms.py`'s `SHAREABLE_NAMES`, in this changelog and in `CLAUDE.md` — was never produced by any build, and the LMS bundle silently carried the syllabus alone. The publish tests did not catch it because they hand-write the `.pubmeta` sidecar. One declaration line; no builder change.

- **`\TeXLibDeclarePublishable` takes an optional coded-suffix.** The coded name is course-identified but not kind-identified, so with the schedule now publishing, both classes in a course cloned to one filename and the later build silently won — and the loser is what gets mailed to the department. `schedule.cls` declares `[Schedule]` (→ `MATH 181.1001_Fall 2026_Fox_Schedule.pdf`); the syllabus deliberately declares none, because its coded name has to match the department convention verbatim. The suffix rides on a `publish-name` override too: that key is course-wide, so without it setting the key re-collides every publishable class onto one name. Pinned by a regression test asserting the two names differ.

- **`\recitation` syllabus section shortcut.** Heads a "Recitation" block in `syllabus.cls`, alongside the eighteen shortcuts already there, and takes the same optional title override for the courses that call the meeting something else (`\recitation[Discussion Section]`, `\recitation[Lab]`). `\recitations` is a plural alias, matching `\communications`.

### Fixed

- **An accessible build of a Notes document with gated solutions died at `\end{document}`.** `\@sol@blankfill` reserves write-in space as a stack of zero-width rules with a `\par` between each — 38 of them for a 7in box — and under tagging every one enters the structure tree as an empty `<text-unit>`. The count does not come out even: a gated body containing a `{center}` leaves one text-unit *end* without a matching *begin*, and the document then fatals with *"The number of automatic begin (N) and end (N+1) text-unit para hooks differ"* — one per such solution. Math 126's Unit 1 hit it ten times, across all six sections. Suspending tagging around the discarded body, which is the obvious fix and the one `texlib-solutions.sty` already applies elsewhere, does **not** help: the leak is in the *blank* box that gets typeset, not in the body box that gets thrown away. `didactic.cls` now sets `\tagpdfparaOff` over the blank fill, scoped to a `\begingroup` so nothing after the solution is affected.

  Untagging that space is right independently of the crash — it is decorative write-in room with no content, so those empty paragraphs were noise a screen reader had to walk past. Gated on `\ifdefined\TeXLibAccessibleMode`; normal builds are untouched.

- **Accessible mode was unreachable from `Ctrl+Shift+B`, and dispatching it by hand was rejected as an unknown mode.** The build mode is declared in three independent places — `MODES` in `Sublime/texlib/texlib.py` (the quick panel), `variants[]` in `TeXLib.sublime-build` (Tools > Build With…), and `args.variant` in `Default.sublime-commands` (the command palette) — and `accessible` only ever landed in the second. So the brain implemented the paired build, `Build With…` could run it, and the picker every other mode is reached through simply did not list it. It failed closed rather than silently: `MODE_TOKENS` is derived from `MODES`, so `TexlibBuildCommand.run` rejected `{"mode": "accessible"}` with *unknown build mode* even when dispatched directly, leaving `Build With…` as the only route to a tagged PDF. `MODES` now carries it, last, since two full builds — the second under lualatex whatever the class's own engine — make it far the slowest mode.

  The palette file had drifted the other way and is re-synced in the same pass: it still offered `Solutions` and `Rubric`, but the build file renamed the first to `Solutions + Rubric` and dropped rubric-only outright, so both entries named variants that no longer existed and did nothing. It now lists `Accessible` too.

  Pinned by `Sublime/test_texlib_modes.py`, which reads all four declaration sites as data — `ast` for the two Python tables, comment-stripped JSON for the two Sublime files — rather than importing `texlib.py` behind stubs, so it checks the files as `deploy.ps1` ships them. It asserts every mode a build variant passes is one `_extract_mode` accepts, that every build variant is also in the picker (one-directional: the picker is allowed `default` and `full`, which are deliberately not variants), that every palette entry names a real variant, and that `MODE_TOKENS` is still derived from `MODES` rather than becoming a second literal to drift against.

- **Every syllabus section shortcut ran its heading straight into the body prose with no space.** `\officehours` on its own line above a paragraph typeset *"Office Hours.Walk-in office hours are listed above"*. The cause is not in `\syllabussection` — it is that each shortcut is a control word with no mandatory argument, so TeX skips the newline that follows it and no space token ever reaches the output. The braced `\syllabussection{Office Hours}` never had the fault, because its closing brace lets the newline become a space, and neither did the `[title]` override form, because `]` does the same. That asymmetry is why it survived: the shipped template uses the braced form throughout, and `examples/Math181-Fall2026/syllabus.tex` was the only document in the repo — or in any live course folder — reaching the shortcuts, so the defect sat visible in its built PDF at five separate headings.

  Fixed with a trailing `\xspace` on the minted command, not a bare `\space`, because the space must NOT appear in the several cases that already read correctly: after the `[title]` form (xparse leaves the newline after `]` in the input), before a paragraph break, before a following list, and where the source already wrote the space itself. `\xspace`'s default exception list — `\@sptoken`, `\par`, punctuation — covers all four. Verified by building each: bare-plus-prose, `[title]`-plus-prose, bare-plus-blank-line, bare-plus-`{itemize}`, same-line prose, the braced form, and the plural aliases.

  No reference images move. The Syllabi module ref is generated from the template, which uses only the braced form, and no scenario uses the shortcuts; module visual gate and all five `syllabi__*` scenarios (`--full` tier, including the multi-page `syllabi__long`) pass unchanged against the committed refs. The one affected PDF, `examples/Math181-Fall2026/syllabus.pdf`, is a build artifact and is not tracked.

## [0.7.0] — 2026-08-20

The pre-semester release: everything since v0.6.1 in one tag, so the installer
can ship it to coworkers before classes start. Headlines: inverse search on
solutions (whole-box, both MC layouts, mechanism documented in SYNCTEX.md),
TeX Live 2026 compatibility for all classes, the UNR-conformant thesis class
gated in CI, `examples/` consolidated under one manifest, 21→33 scenarios, the
class gallery, and `\printbankcatalog` filtering.

### Removed

- **The dead alias `\shufflepages`.** A pre-release sweep of the repo AND every live course folder under `Teaching\` found **zero** uses -- unlike the other deprecated aliases (`	heExamNumber`, `\examversions`, `\overview`, ...), which carry 40-80 live uses each and stay until the planned cross-course migration. An alias nobody uses is pure surface area, and the sweep is what makes this removal safe rather than hopeful. Every doc-comment that still advertised it now names `\shuffle`.

### Fixed

- **`syllabi__long` failed the `--full` scenario tier against its own committed reference.** The scenario's header states its purpose plainly: *"a content-heavy syllabus that **spills onto a second page** -- exercises the running header/footer and multi-page flow."* The committed reference was ONE page -- it contradicted the scenario's documented intent, most likely baked in during a period when spacing compression squeezed the content onto one page, and the later spacing fixes (`a0b1ecf`, `59b9f2d`) restored the intended spill. References regenerated (now two pages, so the page-2 running header is actually pixel-guarded for the first time); full tier is 33/33.


- **The discarded solution box opened mid-paragraph, and everything typeset after it became a child of the enclosing list.** This is the whole of the autoexam half of the TeX Live 2026 tagging failure (#69), and it was never really about autoexam. `{solution}`'s `\ifsolutions` branch makes `\par` its very first action; the discard branch never did. So a source writing `\begin{solution}` with no blank line before it — which the sample bank does, straight after `\end{parts}` — opened the throwaway `\vbox` while the stem's paragraph was still live, and the phantom structure nested inside the enclosing `<L>` instead of landing as a sibling. Everything after it then inherited that parent: the next `\question` tagged as `LI` inside `LI`, following stems as `P` inside `L`. Suspending tagging around the box was never sufficient on its own — the box also has to **start in vertical mode**, which the render branch got for free from its `\par`. `{partsolution}` carried the identical asymmetry (`\par\smallskip` on one side, nothing on the other) and is fixed the same way. Gated on accessible builds, so normal output is untouched.

  tagpdf 0.99w never checked those parent-child relations, so the malformed tree was invisible on TeX Live 2025; 1.0c validates them and the build dies at `\begin{document}` with *"The number of automatic begin (50) and end (44) text-unit para hooks differ"*. **The defect was always there** — only the detection is new.

  Found by bisection, not inspection, and the numbers are worth recording because six plausible explanations died on the way: each real bank problem builds clean **alone**; `quad` — the bank's only `{parts}`-plus-`{solution}` entry — corrupts only what **follows** it. `ratineq+graph` 0, `quad+ratineq` 1, `quad+graph` 6, all three 7 = 1 + 6, exactly additive with `quad` common. Ruled out along the way: `tag_suspend:n`/`tag_resume:n` being renamed (both still exist in 1.0c), `\maketitle`, multi-version emission, page breaking (a 4-page variant scores 0 while a 2-page one scores 7), the inter-problem separator (real, but 2 of 39), and autoexam's `\let`-based `{parts}` wrapper bypassing the environment hooks (no effect at all). Verified 34/34 on TeX Live 2026, where `Exams` and `examples/exam-01` previously fatalled, and 34/34 on the pinned TeX Live 2025.

- **Problem Sets builds again under TeX Live 2026: `{parts}` no longer asks for `leftmargin=*` in an accessible build.** One of the three documents behind the TL2026 tagging incompatibility (#69), and the one with a self-contained cause. `leftmargin=*` is enumitem's *compute the margin from the label width* sentinel rather than a dimension, and under tagpdf 1.0c's block-based lists the accessible branch's `\setlist[parts]` reaches a path that reads it as one — `! Missing number, treated as zero.`, with the `*` itself named as the offending token, fatal. It fires only where `{parts}` nests inside `{problem}`, which is how `pset-template` reaches it; a flat list takes the sentinel without complaint, so a standalone reproduction looks perfectly healthy and says nothing. The accessible branch now gives an explicit `2em` — what `*` resolved to for a bold "(a)" (labelwidth ≈ 1.5em + labelsep 0.5em), and the same explicit margin the accessible `{readings}` list in `texlib-callouts.sty` already carries. **The normal branch keeps `*`, so print output is unchanged**; only the tagged twin moves, and it is not page-identical to the print copy by design. Verified both ways: the document builds on TeX Live 2026 where it previously fatalled, and still passes on the pinned TeX Live 2025.

  Two plausible-sounding diagnoses were wrong, and are recorded so they are not re-run: `tag_suspend:n` / `tag_resume:n` are **both still present** in tagpdf 1.0c, so `texlib-build.sty`'s `\csname` reach does not silently degrade to `\relax`; and `leftmargin=*` is not fatal in a flat list even with the full accessible `\DocumentMetadata`.

- **Every workflow promised a pinned build environment and none had one, so the PDF/UA-2 gate was red from its first run to its last.** All four workflows pin `xu-cheng/texlive-action` by commit SHA and say so — *"a silent TeX Live bump would otherwise invalidate every ref"* — but the SHA pins the **action**, not the toolchain. `scheme: full` resolves to `ghcr.io/xu-cheng/texlive-full:latest`, so TeX Live floated underneath all four; the run log shows `INPUT_TEXLIVE_VERSION:` empty and `Downloaded newer image for …:latest`. When `:latest` rolled to TeX Live 2026 its newer tagpdf broke three accessible-mode builds — `Exams` and `examples/exam-01` fatal with *"The number of automatic begin (50) and end (44/47)"*, `Problem Sets` with *"Missing number, treated as zero"* at `\begin{parts}` — none of which reproduce on TeX Live 2025. `accessible.yml` was therefore never once green, and the `probe/accessible-on-main` run confirms the breakage already sat on `main` rather than arriving with the texinputs work. Setting `texlive_version: 2025` is **not** the fix: at this action SHA that input maps straight back to `latest`. The image itself is now pinned to `ghcr.io/xu-cheng/texlive-full:20260101` — tags are monthly snapshots, and by the action's own convention (TL *N* → `<N+1>0301`) that is the last one before the TL2026 rollover, i.e. TeX Live 2025, matching both the local toolchain and the machine the visual refs are generated on. For `visual.yml` this pins the Alpine base too, and with it the apk ImageMagick whose version decides whether a stale ref reads as a real diff or as an unreliable AE metric. The pin restores the gate; it does **not** fix the TL2026 tagging incompatibility, which is tracked separately and must be resolved before the pin moves forward.

- **The PDF/UA-2 gate reported per-module `PASS` while skipping the PDF/UA checks entirely.** `accessible.yml` installs veraPDF and then fails loudly if the CLI is missing, specifically so a broken install cannot turn the gate vacuously green — and then left the *other* soft-skip on the same path unguarded. `pypdf` was never installed, so every run logged `accessible/PDF-UA [pypdf MISSING -> those checks skipped]` and still reported each module as passing. It is now installed (Alpine's python is externally managed, hence `--break-system-packages`) and asserted importable on the same reasoning as the veraPDF guard. The gate went from `31/34` to `34/34` with the checks actually running. The workflow also now echoes the TeX Live version, whose absence is what made the first failure expensive to diagnose.

- **Installing this package on its own produced a plugin that could not build anything.** `texinputs` — the setting through which every build resolves the classes and the shared `texlib-*.sty` — shipped commented out, documented as *"leave unset to inherit the process environment"*. Sublime inherits no `TEXINPUTS`, and the classes deliberately live in the checkout rather than a TEXMF tree, so unset did not mean "fall back to something sensible", it meant **nothing resolves**: every document failed at `\documentclass` with ``File `didactic.cls' not found``. The only thing that made a machine work was the standalone **TeXLib-Installer** writing the setting for you, which is why this went unnoticed — the author's own `Packages/User` copy is labelled *"NOT shipped"*, and it was doing the load-bearing work.

  Unset now **derives** the path instead. The plugin loads from `<library>/Sublime/texlib`, so the library root is two directories up (`os.path.realpath` first, or the answer lands inside Sublime's `Packages` folder rather than the library, because the installer reaches the package through a junction). The search path becomes that root plus each immediate subdirectory that actually holds a `.cls`/`.sty`/`.lua` — explicit and non-recursive for the same reason the documented list always was: `<root>//` re-walks the whole tree on every pass and lets a stale `.aux` shadow a same-named build. It is generated, not hardcoded, so a new module directory needs no code change.

  Deliberately cautious about being wrong: the derived root is used **only** if it actually contains the core `.sty`. A package copied somewhere else resolves to something that fails that probe, and the default stays empty — preserving the old inherit-the-environment behaviour rather than aiming builds at a foreign tree. An explicit `texinputs` still wins outright, so nobody's configuration changes.

  Doctor now reports the value builds will really use — `explicit`, `derived`, or a `[FAIL]` naming the reason — because "unset" said the same thing on a machine that built fine and on one where nothing built at all, which is the one distinction that check exists to draw. The TEXMF shadow warning is likewise no longer gated on the setting being present, which had silenced it for exactly the users who never configure anything by hand.

  Covered by `Sublime/test_texlib_texinputs.py`, wired into `tests.yml`. The resolution is a real filesystem walk keyed off `__file__`, so the tests copy `texlib.py` into a real `<root>/Sublime/texlib/` on disk and import it from there; mocking `__file__` would test the mock. End-to-end, `\documentclass{didactic}` compiles from the derived value alone, and the same document with no `TEXINPUTS` still fails — so the derivation is demonstrably what makes it work.

### Changed

- **Every example lives under `examples/` and is declared once in `examples/manifest.py`.** The corpus was spread over four registries with four discovery mechanisms — `MODULES` (hand-kept), the scenario glob, `SCENARIO_AREA_MODULE`, `VISUAL_MODULES` — plus three expectation dicts keyed by module. Adding an example meant remembering which subset to touch, and touching the wrong subset **failed silently**: the example simply never ran, and a green suite reported nothing wrong. `tests/fixtures/` and `tests/scenarios/` moved to `examples/fixtures/` and `examples/scenarios/`; `tests/` now holds only `visual_refs/`, which are outputs rather than examples.

  Each manifest entry carries its path, what it is for (`smoke` / `accessible` / `visual` / `showcase`), the substrings its rendered PDF must and must not contain, and **a note saying why the example exists** — the thing a list of paths loses. `smoke_test.py` derives its registries from it, so the build logic is untouched, and the class gallery will render from the same list, which is what stops what you can browse and what CI builds from drifting apart.

  The four corpora are deliberately **not** merged into one: a good teaching example makes a poor regression fixture (too much going on to localise a failure) and a good fixture makes a terrible showcase. They are unified by declaration, not by file. Module templates stay in their module directories for the same reason — a template is the module's public surface, sits beside the class it instantiates, and is referenced by the installer and every module README — and are declared in the manifest alongside the rest.

  `test_texlib_builder.py` now asserts every declared file exists (a manifest pointing at a missing path is the silent failure again), that no randomized module is tagged `visual` (autoexam and quiz shuffle versions, so pixel-diffing them is noise), and that every scenario area maps to a module.

- **The build spec is declared once, and it had already drifted.** `LUALATEX_CLASSES`, `ACCESSIBLE_DOCMETA` and `ACCESSIBLE_MACRO` were literals in **both** `smoke_test.py` and `Sublime/texlib/texlib_build.py`, with a comment instructing the reader to keep them "in lock-step" by hand. They were not in lock-step: `bingo` was in the harness copy and missing from the builder's. A class absent from the builder's set silently gets **pdflatex**, and `bingo.cls` calls `\directlua` unguarded at class load, so it fatals immediately — the only reason nobody hit it is that `Bingo/bingo-template.tex` happens to carry a `% !TeX program = lualatex` directive, which a bingo document written from scratch would not. This is the same failure that cost a debugging session when `thesis` was missing from *both* copies and the smoke build died on `fontspec requires either XeTeX or LuaTeX`.

  They now live once in `Sublime/texlib/texlib_buildspec.py`. That location is deliberate: the plugin host cannot reach repo-root modules, so the constrained consumer keeps the file and the harness reaches down (`sys.path.insert`). Sublime does not auto-load `.py` from a package subfolder, so the module is import-only and can never become a plugin, and it lives inside the junction so it needs no `deploy.ps1` entry. `test_texlib_builder.py` now walks every `.py` in the tree and fails if any of them redefines the shared constants, so a copy cannot creep back.

- **The library's sample banks are `problem-bank.tex`; `bank.tex` stays a supported name.** `Bank/` held three files called "bank" with three unrelated roles — `bank.cls` (the preview class), `bank.tex` (a bare fragment that must **never** carry a `\documentclass`, or every `\loadbank` breaks) and `bank-template.tex` (the wrapper document). The file whose name most suggested "the bank document" was the one that breaks everything if treated as one. Worse, `bank.tex` is not just a filename but a **discovery convention**: the classes and both Python tools auto-load a sibling of that name, and `didactic.cls` already carried a comment recording that a bare `Bank/bank.tex` could match *the library's own sample* ahead of a course's real bank. Renaming the two library samples removes that shadowing at its source. **Nothing needs migrating** — every existing course folder keeps working, because all three resolvers now probe `problem-bank.tex` first and `bank.tex` second.

- **`preferred_pdf` — choose which of a multi-copy exam's PDFs the viewer actually opens.** A `\versions{A,B,C}` exam built with solutions compiles all six copies into one PDF and is then sliced into a file per copy, but the post-build handoff had only ever named `<base>.pdf`, so every `Ctrl+B` put the combined build in front of you and the copy you were actually reading — `<base>_A_solutions.pdf`, almost always — had to be reopened by hand, every time. The new `TeXLib.sublime-settings` key names the one to open: `"solutions"` resolves to the first solutions copy the build produced (`_A_solutions`, or `_Solutions` for a `.spl` key build), `"student"` to the first student copy, a literal suffix like `"_B_solutions"` to exactly that, and `"combined"` (the default) leaves the behaviour unchanged. Resolution happens against what **this** build produced and always falls back to `<base>.pdf`, so a student-mode build, a single-version document, or a build whose slicing was skipped for want of pypdf opens the combined PDF rather than nothing: the setting is safe to leave on while you work on something that isn't an exam. `latextools_jumpto_pdf` cannot be part of this — read it and `pdffile` is *built* from `get_tex_root()` + `get_jobname()`, never taken as an argument, so no combination of args aims it at a slice and taking its branch would have pulled the combined PDF back to the front and undone the preference. That is a deliberate exception to the couple-by-command-name rule, taken because the command channel provably cannot express the target; it degrades to a plain open on any failure, and it stays viewer-agnostic because `forward_sync(pdf, tex, line, col)` is the signature every viewer plugin implements. `TeXLib: View PDF` and `TeXLib: Forward Sync` aim at the same copy the last build resolved, rather than snapping back to `<base>.pdf`. - **Known, and older than this: forward *search* into a multi-version exam is unreliable — in the combined PDF as much as in a slice.** Worth recording because it looks like a cost of the above and is not. Measured with the `synctex` CLI against a `\versions{A,B}` + solutions build: a line in the document's own body resolves to **no page at all**, because `autoexam_run_versions` re-emits the body through `<base>_autoexam_body.tex` and `\input`s that, so body nodes are attributed to a scratch file the build then deletes; and a bank line resolves to exactly one page, because the per-problem SyncTeX redirect gives `bank.tex` one `Input:` tag per `\@@input` (ten of them in a two-version fixture) and a forward lookup resolves the file to a single tag. - **Sliced per-version copies get their own SyncTeX map, so inverse search works inside them.** A sliced copy is pages carved out of the combined PDF with pypdf, and a viewer looks for `<its own name>.synctex` — never the parent's — so double-clicking anywhere in `<base>_A_solutions.pdf` had always done nothing at all. That was invisible while the combined PDF was the only one anyone opened; it becomes the whole story once `preferred_pdf` can make a slice the copy you live in. `_slice_synctex_for_copies` now cuts `<base>.synctex` down to each copy's own page span, keeping the `{n … }n` sheet blocks in range and renumbering them from 1. Records inside a sheet are copied untouched — a record carries a file tag and a source *line*, never a page, so a page-slice cannot invalidate one — and every `Input:` row survives wherever it stood, including rows for dropped sheets, because they are the tag → file table the surviving records index into. The one genuinely fiddly part is the `!N` anchors: `N` is the byte distance from the previous anchor's own offset, and SyncTeX *seeks* with them, so a rewrite that copied them forward would drop a reader into the middle of a record. They are dropped on the way in and recomputed on the way out, which is also what lets the rewrite round-trip a real map byte-for-byte when nothing is excluded — asserted as a test, since it is the strongest available statement that the cut is faithful. `Count:` is left as the parent's: it sizes the parser's record table, where an over-estimate is harmless and a wrong-but-plausible value is not. `texlib_pdfpost` reports each produced file's page span (new `ranges` key) to make this possible — the page count is only known there, where pypdf has the PDF open. Best-effort throughout: a build with `-synctex=0`, or a copy whose map cannot be written, is silently back to where it was. Scenario 11 of `test_synctex_integration.py` drives the real `synctex` CLI at a needle inside `autoexam_A_solutions.pdf` and asserts it answers *identically* to the combined map for the same physical page, which an "it resolves to bank.tex" check alone would not catch an off-by-one in.

### Changed


- **Accessible mode is now a PAIRED build: the normal PDF and the tagged one, side by side, from one invocation.** `--texlib-mode=accessible` previously compiled only the tagged copy and left `<base>.pdf` as whatever an earlier build happened to leave there — so getting both meant building twice and remembering to. It now runs the normal build first, through the ordinary `_build_once` path (full biber + cross-reference settling loop), then the tagged pass, leaving `<base>.pdf` and `<base>_accessible.pdf` together. The two halves deliberately use **different engines**: the normal half keeps the class's natural engine, so a syllabus's primary PDF is still pdflatex output and is byte-identical to a plain `Ctrl+B`, while only the tagged half is forced to lualatex (MathML tagging is a Unicode-engine feature). The old code overrode the engine for the whole mode, which — once the mode also produced the primary PDF — would have silently re-rendered every pdflatex class under lualatex. Order matters and is asserted: `_postprocess` copies the primary PDF back and only then reads the `.pubmeta` sidecar and publishes, so the normal half has to run first. The halves never share an output directory (the tagged one is redirected to `a11y/` under the aux dir), so neither can clobber the other, and `\jobname` stays the document's real base name because several TeXLib engines key off it. Pairing rather than replacing is the point: `tagging=on` costs real visual fidelity — tcolorbox theorem wraps are dropped because their inner list breaks under tagging — so the normal PDF stays the pretty one for print and lecture, and the tagged twin is the one a screen reader can navigate.

- **The tagged build emits both MathML methods (`mathml-AF,mathml-SE`), not just structure elements.** PDF readers split on which method they understand, and the split falls across how a student actually opens the file: AF (associated files) is what Firefox's built-in viewer and Foxit read — the in-browser path from an LMS link — while SE (structure elements) is what Adobe Acrobat reads. Emitting SE alone left every reader on the other side of that split hearing "x 2 plus y 2" instead of "x squared plus y squared". `pdfstandard=a-4f` was already set, and its "f" (files) is precisely the conformance level that permits the AF attachments, so the capability was being paid for and not used. Set in both `Sublime/texlib/texlib_build.py` and `smoke_test.py`, which must stay in lock-step. Deliberately **not** set: `\tagpdfsetup{math/alt/use}`. It raises the score an Ally/UDOIT-style checker reports, but it does so by replacing the MathML with flat alt text that hides the real markup from screen readers — a better number for worse accessibility.

- **An accessible build publishes its TAGGED half to the shareable LMS names.** The publish step's copies (`<course>.<section>_<term>.pdf` and the generic `Syllabus.pdf` / `Tentative Schedule.pdf`) are precisely the files that go up to WebCampus, where an untagged PDF is exactly what the LMS accessibility checker flags — and until now the LMS bundle carried the untagged build no matter how much tagging work had been done. `_publish_source_pdf` picks the tagged file when one exists, gated on *this* build having produced it, so a stale `<base>_accessible.pdf` from an earlier run can never be published behind a normal build's back. The cost is nil for the only two publishable classes: syllabus and schedule box no theorems, so the tcolorbox fallback that makes the tagged variant plainer elsewhere never fires for them. `package_for_lms.py` needs no change — it bundles the generic names, whose content is now the tagged PDF.

- **The grading rubric moved out from over the solution and under it, beside the common errors.** `\rubric` items were `\llap`'d onto the "Solution." header line with natural height and depth, so `\par` charged that line for the whole overlay box — a four-criterion rubric shoved the solution four lines down the page whether or not its first line came anywhere near the overlay. (The old comment called this an accepted trade-off; it is not, once a rubric routinely runs four items.) `{commonerrors}` had the opposite problem: it typeset itself inline at whatever point in the source the author wrote it, so it landed mid-solution as readily as after it. Both now render in a footer beneath the worked solution and inside the same green box — common errors left, rubric right, widths split 60/40 off the solution `\vbox`'s own `\hsize` — laid out by `\@emit@sol@footer` at `\end{solution}`, when every `\rubric` call and the `{commonerrors}` body are known. Nothing pushes the solution anywhere any more. The two panels are styled as a matched pair (same `\fboxsep`, tint depth, `\small\sffamily`, bold coloured heading; teal for what the work earns, red for what it loses), and `\@rubricline` gained `\hangindent` so a wrapped criterion keeps its continuation under the description instead of running back to the label column — the hanging shape `{commonerrors}` already had. A lone panel keeps to its own side rather than stretching. `{partsolution}` emits its rubric beneath its prose for the same reason.

- **Common-error items are labelled with the deduction they cost, in place of a bullet.** `\item[4]` prints `[-4 pts]` in the label column, where the rubric beside it prints what the step earns — so the two panels read as one ledger rather than as a list of criteria next to a list of prose. The magnitude is what the author writes and the minus is supplied by the label, so the panels can never disagree about the sign; `\item[0]` prints a muted `[0 pts]` for a wasted-effort note that carries no penalty. A bare `\item` still renders the old square bullet, so documents predating the labels are unaffected — LaTeX routes both `\item` and `\item[x]` through `\makelabel`, so the fallback is detected by giving the list a `\relax` default label and comparing against it. A non-integer optional argument is not supported: the label column is for a number of points, and prose belongs in the item body.

- **`{commonerrors}` captures its body instead of typesetting it.** Now a `\NewEnviron`, so the body is stashed and rendered by the solution footer rather than at the point of use — which is what lets its width be chosen against the rubric beside it, and what makes placement independent of where in the source the block sits. Nothing is typeset at all when `\ifrubric` is false, where the old version still set the body into a discarded `\vbox` (and so could choke on fragile content it was never going to show). Outside a `{solution}` it renders where it stands, in the same panel style. Verbatim content remains unsupported, as before.

- **Multiple choice no longer carries a grading rubric.** A rubric apportions partial credit, and a multiple-choice item is all-or-nothing — there is nothing to apportion, so `\rubric` overlays and `{commonerrors}` blocks were printing against items where they could never be applied. `{mcproblems}` now sets `\rubricfalse` for its whole section (`texlib-problembank.sty`); the flag is local to the environment group, so a `{problems}` section elsewhere in the same document still renders its rubrics normally. Emission happens in `\@texlib@psection@end`, which runs inside that group, so the whole section is covered. Bank sources keep their MC `{commonerrors}` blocks — they are useful distractor notes while writing an item, they cost nothing in any build, and deleting one line restores printing. `test_mode_effects.py` gains an assertion, run for every mode of both exam and quiz classes, that the MC rubric needle never appears while the FR one still does.

- **`\ShowRubric` implies `\ShowSolutions`; the rubric-only build mode is retired.** A rubric annotates a worked solution, so a rubric-without-solutions build renders point apportionments and common-error notes floating against blank answer space — of no use to anyone. Worse, `\ShowRubric` alone previously rendered *nothing at all* on exams and quizzes (`\ifsolutions` gates the solution box the rubric overlay lives in), so the mode silently produced a plain student copy. `texlib-build.sty` now raises `\solutionstrue` with `\rubrictrue`, and `autoexam.cls` gives `\ShowRubric` the same `dual` copy mode as `\ShowSolutions` — without which the rubric would land in the copy the builder then slices as the *student* PDF. Sublime's `solutions` mode injects both macros and is captioned "Solutions + Rubric"; the `rubric` mode is gone from `TeXLib.sublime-build`, the native command palette, and `MODE_MACROS`. `key` deliberately does **not** gain the rubric: an answer key is student-facing, and point deductions are grading-internal. The `ShowRubric` row of `test_mode_effects.py` flips from "renders nothing" to "renders solutions + rubric".

And because the title composes through `\GetCourse`, the accessible build's title check doubles as a metadata-level assertion that the fixture's own `\SetCourseTitle` round-tripped — the `\texlib@doctitle`/`\TeXLibDeclareDocTitle` hook had no direct test before this, only class smoke builds that soft-skip whenever veraPDF is absent. The `KNOWN GAP` paragraph in `course-metadata.sty`, which still described Schedule as shipping untitled, is corrected to match.

- **Hidden worked content no longer leaves phantom structure in the tagged PDF.** Gating a solution or a worked lead-in off does not stop it being typeset: the classes capture the body into a throwaway `\vbox` and drop the box. No glyphs ship — but tagpdf still walks the material, and when the box opens while a paragraph is live the phantom nests *inside* it, giving `Table 5 P-Part` + `P-P` violations for content that never reaches the page. `\texlib@acc@tagsuspend`/`\texlib@acc@tagresume` moved from `texlib-solutions.sty` to `texlib-build.sty` — `didactic.cls` needs them and does not load that package, and `texlib-build` is the one build-mode package every class shares — and they now guard three sites: the `{solution}`/`{partsolution}` envs, didactic's `\pf`/`\solution` lead-ins, and its boxed `{solution}`. This was the last thing keeping `didactic-template` from conforming, so all nine classes now pass veraPDF ua2. The fault only appears MID-PARAGRAPH: with a blank line before the environment the phantom lands as a harmless sibling and the document conforms even with the bug present, which is why the new `tests/scenarios/notes/worked-gated` fixture deliberately opens one with the paragraph still live — it fails without the fix and passes with it.

- **`cleveref` made the accessible build of Notes and Problem Sets fatal, and it was never the tcolorbox everyone suspected.** Both classes loaded `cleveref`, which patches amsthm's `\@begintheorem`; under `\DocumentMetadata{tagging=on}` that patch leaves a block-level list open when the new tagged block implementation typesets a theorem head, so the *first* definition-style or remark-style environment died with "! LaTeX Error: Something's wrong--perhaps a missing \item." and the run ended "no output PDF file produced". tagpdf names the underlying structure fault one line earlier — "Parent-Child 'pdf2:L' --> 'pdf2:Sect' ... is not allowed" — a list parenting a section. plain-style theorems happen to survive it, which is why the failure looked selective and pointed at the theorem taxonomy rather than at a cross-reference package: `\begin{theorem}` built fine while `\begin{definition}`, `\begin{remark}`, `\begin{example}` and `\begin{note}` all died. Bisected to cleveref by elimination — bare `article`+`amsthm` with `\theoremstyle{definition}` tags cleanly, `texlib-theorems`+`texlib-thmenv` alone tag cleanly, `nameref` alone tags cleanly, and adding `cleveref` (with or without its options) reproduces it every time. New `texlib-crossref.sty` routes `\cref` by build: cleveref exactly as before in a normal build (same `[capitalise,nameinlink]`, unchanged output), and zref-clever — cleveref's maintained, tagging-aware successor — plus a `\cref`/`\Cref`/`\cpageref`/`\labelcref` shim in an accessible build. Two traps in that swap: zref-clever accepts **no load-time options at all** (it hard-errors and points you at `\zcsetup`), and it spells the capitalisation key `cap`, not `capitalize`. `\crefname`/`\Crefname` cannot be honoured faithfully — zref-clever supplies its own type names through a different interface — so they warn once rather than stopping the build. Notes now builds a tagged PDF (it still fails two PDF/UA-2 clauses); Problem Sets is now **fully PDF/UA-2 conformant**.

- **Inline `\begin{enumerate}[...]` keys are fatal under tagging, which is what killed the Problem Sets `{parts}` list.** `pset.cls` built `parts` as `\begin{enumerate}[label=..., leftmargin=*, topsep=2pt, parsep=2pt]`, and the new `block` implementation takes over the optional argument and rejects enumitem's keys outright: "! Package block Error: Some keys specified on the enumerate environment are unknown." The message invites a hunt for the one bad key and there isn't one — it fires on *any* key, a lone `parsep=2pt` included. Preamble `\setlist` declarations are still honoured, so the accessible branch declares the same keys with `\setlist[parts]` and rebinds `\part` through `\AtBeginEnvironment`; the normal branch is left exactly as it was, so normal output is unchanged. The two differ slightly in `labelsep`/`itemsep`, which the `\newlist` `parts` carries from `basic-utilities` and the inline form took from `enumerate`'s defaults. The same fault hit `{readings}` in `texlib-callouts.sty`, which opened `\begin{itemize}[leftmargin=2em, ...]` — so **every lecture containing a Readings block produced no accessible PDF at all**, and the cause was library code rather than anything in the document. That one is routed through a `\newlist`-declared `texlibreadings` list in the accessible branch, same shape as `parts`. A sweep of the tree found no other live inline-key list: those two were the only ones in any `.sty`/`.cls`. Note that `Notes/README.md` still advertises `\begin{enumerate}[(a)]` to users, which is fine in a normal build and fatal in a tagged one.

- **`.schedmeta` now survives a Sublime build instead of being stranded in `%TEMP%`.** The sidecar is written through the same aux routing as every other artifact, so with `-output-directory` active — which the Sublime builder *always* passes — it landed in `%TEMP%\texlib-aux\<hash>` and never came back. `_copy_back_from_aux` moved only `<base>*.pdf`, `*.synctex.gz` and `*.spl`, so after `Ctrl+B` the standalone sync program either reported "no .schedmeta — build the schedule first" for a schedule it had just watched build, or silently read a leftover from an older bare-CLI run and reconciled a calendar against a grid that no longer existed. `<base>*.schedmeta` joins the copy-back patterns: its consumer lives outside the build, so like the PDF it belongs beside the source. (`.schedmap` deliberately stays put — its consumer *is* the builder, which probes both directories itself.) Covered by four new checks in `Sublime/test_texlib_builder.py`. Only bare CLI builds with no `-output-directory` were unaffected, which is why the feature looked correct when it was developed.

- **A build that finishes after you switch tabs now opens the PDF it actually built.** The Sublime plugin's post-build handoff named no target: LaTeXTools' `jumpto_pdf` resolves its PDF from `window.active_view()` at the moment it is called, and the native build is asynchronous — so moving to another `.tex` tab while a build ran sent SumatraPDF that tab's PDF instead of the one just produced (and if the tab you moved to wasn't a `.tex` file at all, `jumpto_pdf` returned early and no PDF opened, silently). The document being built is now captured when the build *starts* and carried to the handoff: the plugin still delegates to `jumpto_pdf` while the active view resolves to that same root — including an `\input` child, where a forward sync from the cursor is meaningful — and otherwise opens the built PDF by explicit path through `latextools_view_pdf`'s `file` argument, with no forward sync (the cursor that would drive one is in a different document by then). That second path also runs LaTeXTools' delayed-`bring_to_front` focus hack itself, honoring `keep_focus` / `disable_focus_hack` / `<platform>.keep_focus_delay`, because `view_pdf` hardcodes `keep_focus=False` and Sumatra pops to the front regardless — so both paths leave focus where your settings say. Covered by `test_texlib_runner.py` (now also wired into CI). The same drift exists upstream in LaTeXTools' own `make_pdf.py`, so the legacy *Build With: TeXLib* builder path is unaffected by this fix.

- **Rebuilding the accessibility gallery no longer opens a console window for every tool it runs.** The Sublime launcher ran `a11y_gallery.py` under `pythonw.exe`, and a GUI-subsystem process owns no console — so each of the dozens of console tools the generator spawns (lualatex, veraPDF, pdftoppm, magick, several concurrently) had to allocate its *own* console, each one a visible window. `CREATE_NO_WINDOW` on the parent could not help: there was no console to suppress. The launcher now uses console `python` with that flag, which yields a single *invisible* console the whole descendant tree inherits. Fixing it at the launcher leaves `a11y_gallery.py` and `smoke_test.py` free of Windows GUI concerns, so both stay clean for CLI and CI use; command-line runs inherit the real console and are unchanged.

- **The build-failure panel's "full build log — double-click to open" link now opens the log.** The link was assembled from the tex root's basename *with* its extension, so it named `doc.tex.log` in the aux directory; the engine's jobname is the extension-stripped base name (`TexlibBuild.base_name`), so the file sitting there is `doc.log` and double-clicking the link did nothing. The runner now derives that name inside `_aux_log_path` from the tex root alone rather than taking it from the caller — the display basename the status bar and report header want is not the one the filesystem wants, and passing the former in is what went wrong. The regression test reads the target directory and jobname back off a real recorded engine invocation instead of a hand-written path, so the link stays tied to whatever the engine is actually told to write.

## [0.5.0] — 2026-07-30

### Added

- **Multiple-choice problems may have more than one correct option.** `\cchoice` is now repeatable — mark every right answer (equivalent antiderivative forms, "select all that apply") and the key reports them in presented order as `Answer: B, D`. All correct options are always-present, so `\shuffle`'s subset selection can never drop one and strand the key. A single `\cchoice` still renders the bare letter, so existing keys are byte-identical; the old "only the first counts as correct" warning is gone.
- **`\cchoiceif{lua-expr}` — correctness that follows the random draw.** An option marked this way is correct only when the expression holds at typeset time, so `\setrng{a}{-6}{6}` can decide whether "increasing" or "decreasing" is the answer for this version. Conditions are evaluated in the same sandbox as `\calcvar` (the `math` library plus every stored var). The condition is a *braced* argument, not bracketed, so it can't be confused with option text opening on an interval. Because the conditions read variables the **stem** sets, a `\cchoiceif` problem defers its whole MC tail to a follow-up `\pbank@lua` call (the deferral `pbank_stage_solution` already uses) — otherwise the tail would be generated before TeX had executed the stem, and read the previous problem's draw. Only `\cchoiceif` problems take that path, so every existing exam keeps its byte-identical option order.
- **`\ifvar{lua-expr}{then}{else}` — branch prose on the current draw.** The prose analogue of `\cchoiceif`, usable anywhere in a stem, a part, or a `{solution}`; both branches are `\long`. A condition that fails to compile warns and takes the `else` branch rather than aborting the build.

- **Accessible (tagged PDF/UA) build mode — a screen-reader-friendly `<base>_accessible.pdf` produced alongside the normal PDF.** A new build mode (`--texlib-mode=accessible`, Sublime "Accessible" variant) compiles a second, tagged copy of any document without touching the primary one. Tagging can only be switched on by `\DocumentMetadata{tagging=on, …}` issued *before* `\documentclass`, so it cannot be a class option — the builder injects it on the command line ahead of `\input{<doc>}` (the same prefix trick used for `\def\ShowKey{}`) and forces lualatex (MathML math tagging is a Unicode-engine feature). Config mirrors UNR's Hurtado v0.5 thesis template: tag structure + MathML math (`mathml-SE`) + tagged table headers, `pdfstandard={ua-2,a-4f}` (PDF/UA-2 for accessibility, PDF/A-4f for archival). The tagged build writes into an `a11y/` aux subdirectory under the document's **real** jobname (several TeXLib engines key off `\jobname` — autoexam reads its body from `<jobname>.tex`) and is copied out as `<base>_accessible.pdf`. `texlib-build.sty` exposes `\ifTeXLibAccessible` (from the compile-time `\TeXLibAccessibleMode`) so classes/packages adapt. **Verified against veraPDF 1.30.2: Syllabi, Quizzes, Report Cards, Bank, and Bingo produce fully PDF/UA-2-conformant output.** The math-heavy classes (Notes, Problem Sets, Exams, Schedule) build but do not yet fully conform — documented per-class.
- **`smoke_test.py --accessible` — dependency-free PDF/UA structural checks plus optional veraPDF rule-level validation.** Builds each target's tagged variant and validates it. `check_pdfua_structure` (pypdf, always available) asserts the PDF/UA markers — `/MarkInfo /Marked`, `/StructTreeRoot`, `/Lang`, `ViewerPreferences/DisplayDocTitle`, a title (XMP `dc:title` or DocInfo `/Title`), and XMP `pdfuaid:part` — catching the "builds fine but isn't really tagged" regression a build-only run misses (verified to fail every marker on an untagged PDF). `check_verapdf` (soft-skips when veraPDF is absent, like pdftotext/ImageMagick) runs full ua2 conformance and, on failure, parses veraPDF's XML report to name the failed ISO clauses (e.g. `8.11.1`) rather than a bare "non-compliant".
- **`\TeXLibMathIntent{intent}{math}` (texlib-mathutils) — MathML alt-text for ambiguous notation.** Attaches a MathML `intent` so a screen reader reads a symbol as given during an accessible build; a no-op otherwise. Single math node only (luamml drops the intent on multi-node/delimited expressions), so it suits scripted operators and single symbols — e.g. `\newcommand{\sininv}{\TeXLibMathIntent{inverse-sine}{\sin^{-1}}}` reads "inverse sine" instead of "sine to the negative one power".
- **`\gradebound{<lower>}{<upper>}` (syllabus) — aligns the grade-range column on the `x`.** A plain centred cell centres each range as a whole string, so "90 ≤ x" and "80 ≤ x < 90" put their x's in different places. `\gradebound` pads each side to a fixed width and anchors the x on a common axis (`A & \gradebound{90 \leq}{}`, `B & \gradebound{80 \leq}{< 90}`). Syllabus templates updated to the new syntax. (Known cosmetic limitation: an empty *lower* bound — the open-ended F row — sits 1.8pt off.)

### Changed

- **The Sublime plugin now *detects* how many engine passes a document needs instead of reading it off the log.** After each pass the build core fingerprints the cross-pass state in the aux dir — `.aux` (minus biblatex's own `\abx@aux@read@bbl*` rerun bookkeeping, which is not document state and flips once even in a document with no bibliography), `.toc`/`.lof`/`.lot`/`.lol`, `.out`, `.bbl`, index/glossary and beamer artifacts — and compares it with the state that pass started from. The engine re-runs while that keeps changing or the log asks, and the fingerprint outranks the log in both directions. **More complete:** `autoexam.cls` defines `\@testdef` as a no-op to silence the multi-version label oscillation, so an exam whose `page X of Y` footer (`\pageref{@lastqpage@<ver>}`) moved to another page emits no warning at all — the changed `.aux` is the only evidence there is, and a silent-log state change now earns a settling pass. **More honest:** when a pass consumed and produced byte-identical state, the next pass gets identical input and produces identical output, so a log line still asking for one is vetoed (this is what drops the post-biber rerun on a `.bib`-edit rebuild from 4 commands to 3). Non-convergence is bounded three ways rather than silently truncating: a state cycle (A→B→A) stops at the repeat with a message, a silent log buys at most `STATE_ONLY_RERUNS` passes (a bank document with no `\setexamseed` draws fresh values every pass, so once a draw moves a page break its `.aux` never repeats), and hitting the `MAX_RERUNS` ceiling — raised 3 → 5 now that the loop ends on evidence rather than on a count — is reported. Measured against one document per class (the `Math181-Fall2026` example course plus the `schedule`, `report-card`, `bingo`, `pset` and `bank` templates), eight of the nine take exactly the passes they did before — 2 cold, 1 warm. The ninth, `report-card`, goes from 1 cold pass to 2: on a cold aux dir the baseline is the *absence* of state, so pass 1 writing any `.aux` counts as a change, and report-card's `.aux` happens to be a fixed point from pass 1. That cost is deliberate — it is the same cold transition that fixes the exam footer, where nothing asks for the pass: `autoexam` guards `\pageref{@lastqpage@<ver>}` with `\@ifundefined` and falls back to `\numpages`, so pass 1 reports no undefined reference and the gutted `\@testdef` reports no changed label on pass 2. It is one pass per document per aux-dir lifetime; warm builds are untouched. Opt out with `"detect_reruns_by_state": false` (or `TEXLIB_STATE_RERUN=0`).
- **The autoexam cover carries the term + section; the running header carries the part.** `\GetTermSection` moves off the right header slot and onto the title block (under the course line, emitted only when non-empty). The right header instead shows the current problem-section — "Part I — Multiple Choice", "Part II — Free Response" — *in addition to* the shared core's in-body `\section*` heading, which is unchanged, so a reader who opens to any page still knows which part they are in. The label is carried as a page **mark** and read back via `\rightmark`, not as a global macro: `\problems@begin@hook` skips its `\clearpage` after an `{mcproblems}`, so two parts can share a page, and `\rightmark` (`\firstmark`) heads that page by the part it *opens* in. `\blankpage` moves "Scratch Work" from the center header to the right for the same reason. Only `autoexam.cls` overrides `\texlib@partheading` (adding the mark to the stock heading); quiz is untouched. Affects `tests/visual_refs/exam__standard-*.png` — regenerate with `smoke_test.py --visual --update-refs`.
- **The answer-key multiple-choice answer line now sits exactly where the blank copy's does.** The key used to print its letter at the foot of the narrow solution column, stranding it mid-problem while the page's leftover height pooled as dead space under the last problem — so a key page and its blank counterpart no longer lined up. The letter now goes full width, flush right, at the foot of the problem's slot just above the separator rule, floated there by a new `\@mc@keyanswergap` mirroring `\@mc@answergap`, and boxed to the width of the student's answer rule so `Answer:` lands at the same x in both builds (measured identical; problem baselines track within a few points). Two traps made this less obvious than it looks. `texlib-solutions.sty` collapses `\stretch` itself to `0pt` under `\ifsolutions` (so a bank problem's bare `\vspace{\stretch{n}}` can't shove the solution to the page bottom), which silently voids any `\stretch`-based gap in exactly the build it is meant for — hence `\vfill`, the same glue order reached without the neutered macro. And glue emitted as a problem's *last* item is the end of the vertical list when the next `\question` runs `\addvspace`, whose `\removelastskip` drops it (an infinite skip compares as its `0pt` natural size, so it always loses) — hence emitting the answer line after the gap, which protects it. The boxed letter is flush left inside its frame rather than centred, so `pdftotext` still extracts `Answer: X` as one line for the tooling that scrapes it. Set `\@mc@keyanswergap` to `\relax` for the old packed behaviour. Free-response keys are unchanged.
- **Solutions and answer-key covers drop the name rule and the postscript.** Both address the student sitting the exam, so every copy that shows answers (`\ShowKey`, `\ShowSolutions`, `\keys`, `\justsolutions` — the gate is `\ifsolutions`) omits `Name: ______` and `\GetExamPostscript`. Student copies are unchanged.

- **`{challenge}` now hides its worked response outside a solutions build.** A challenge is posed to be attempted, so everything after a `\solution` / `\answer` / `\ans` / `\pf` inside one is suppressed unless `\ifsolutions` is set (`\ShowSolutions`, `\ShowKey`, source `\solutions`, …); the challenge *statement* always renders. All four lead-ins are gated, not just `\solution` — the others give the result away just as completely. `example` / `exercise` / `question` are untouched and stay always-visible, where the worked answer is the exposition. Opt out with `\TeXLibShowChallengeSolutions` in the preamble (`\TeXLibHideChallengeSolutions` restores the default). Implementation note: a lead-in is an inline marker, not a group, so hiding has to swallow the rest of the environment — it is collected into a discarded `\vbox` (the trick `texlib-solutions.sty` already uses for a suppressed `{solution}` box) that `\texlib@worked@end` closes. Inherited caveat: discarded material is still typeset into the dead box, so counters stepped inside it advance and `\label`s fire — keep numbered constructs out of a challenge's response. `didactic` already gated `challenge` (and `exercise`) through its own hooks, which are registered later and therefore win, so `\TeXLibShowChallengeSolutions` would have silently done nothing there; `didactic.cls` now points that name at both flags, so the one public knob behaves identically in every class — verified by building `didactic` and `pset` in default, solutions, and opted-out configurations.


- **Every class now sets a PDF document title.** Classes render their title visually from course metadata but never set `\title`, so hyperref's `pdfusetitle` had nothing to use and the PDF shipped untitled — a blank viewer/browser tab in normal builds, and a hard PDF/UA failure (clause 8.11.1) in accessible ones. `course-metadata.sty` gains `\TeXLibDeclareDocTitle`, fed to `\hypersetup{pdftitle}` at `\AtBeginDocument`, defaulting to "<course> <term>"; each class declares its own noun (Syllabus, Tentative Schedule, Lecture Notes, Problem Set, Report Cards, Bingo, Exam, Quiz, Problem Bank). `bingo.cls` and `schedule.cls` — the only two classes not loading hyperref — now load `hyperref[hidelinks]` so the title reaches them (this alone takes Bingo to full PDF/UA-2 conformance).
- **The Problem-Set `{hint}` environment is now a `\hint` command. (Breaking.)** `\hint` is a run-in "Hint." lead-in matching how `\solution`/`\answer` are used inside problem environments — you write the hint as following prose instead of wrapping it in `\begin{hint}…\end{hint}` — and it sheds a tcolorbox (which breaks under PDF tagging). **`\begin{hint}…\end{hint}` no longer exists**; convert call sites to `\hint …`. The two in-repo uses (pset template, Math181 lecture) were converted.


### Fixed

- **`\\` inside a `\directlua` chunk silently gutted several classes under PDF tagging.** `\directlua` *expands* its argument, and three Lua chunks embedded a `"(.*[/\\])"` directory pattern whose `\\` is a TeX control sequence that merely stringifies into two backslashes in a normal build. The tagging code redefines `\\`, so under `\DocumentMetadata` it expanded to garbage (`invalid escape sequence`), the chunk died at load, and every engine global went nil — leaving the accessible schedule empty, the exam truncated, the quiz's second problem mis-rendered, and Report Cards/Bank failing to build. Fixed in `schedule.cls`, `report-card.cls`, and `texlib-problembank.sty` by building the separator Lua-side via `string.char(92)`, which no TeX macro can touch. (Normal builds were unaffected; the same pattern inside real `.lua` files is fine — those are never TeX-expanded.)
- **Accessible exams and quizzes lost their subproblem point values.** exam.cls delivers "(N points)" via `\everypar`, which PDF tagging takes over — so under `\DocumentMetadata` the points vanished silently from a graded copy handed to a student. In an accessible build they are now re-emitted inline (hooking `\@readpoints`, the one path exam.cls takes for a points-bearing item), with the singular "point" for N=1; normal builds are untouched.
- **Accessible exam instruction bullets were centred instead of left-aligned.** The cover renders the instructions box inside a `center` environment; under tagging that becomes a centred structure block whose alignment leaks into the bullet list. No TeX-level reset overrode it — a `flushleft` environment does. Fixed in `texlib-instructions.sty` (accessible builds only; normal builds keep their justified layout).

- **The visual gate no longer turns an ImageMagick defect into a phantom layout regression.** Alpine began shipping **ImageMagick 7.1.2-27 (Beta)** mid-week, which is why the *same* `main` commit went green on 2026-07-28 and red on 07-29 with nothing committed in between. Two independent faults stacked. (1) `_compare_pages` read the `-metric AE` count with an integer-only pattern (`1234`, optionally `1234 (0.00188)`); the Beta emits scientific notation, that pattern rejected it, and because `compare` also exits non-zero whenever the images differ *at all*, the "no metric line" fallback returned a fabricated `10**9` — which reads exactly like a page-dimension mismatch and sends you hunting the wrong thing. The parser now accepts the integer, real and scientific spellings, and a genuinely unreadable result raises `CompareFailed` so the tool reports itself in its own words. (2) The Beta's AE value is itself wrong: for a pair that 7.1.1 measures at 30 differing pixels it reports `1.59597e+06 (1.59597e+06)` — a count larger than the 935 000-pixel page, with a "normalized" figure identical to the raw one. Since AE counts differing pixels it cannot exceed the page's pixel count, so a figure that does is now reported as an unreliable metric rather than as drift. Byte-identical pages still compare as `0` and pass, so the gate keeps working; what it loses on this build is the 0.2 % fuzz tolerance, which makes references effectively exact-match until the Beta is superseded. Consider pinning `imagemagick` in `.github/workflows/visual.yml` if Alpine stays on a Beta. The `quiz__solutions` reference — a genuine 30 px drift, well under budget, but no longer forgiven by the broken metric — is regenerated here.

One source of build behavior, nothing to drift. `Ctrl+B` runs the native path; `Tools → Build With → TeXLib` still runs the adapter. - **`\ShowKey` / source `\keys` now builds the exam answer key.** Previously `\ifkey` was never consulted in `autoexam.cls`, so `\def\ShowKey{}` was a silent no-op and the key had to be requested via `\ShowSolutions`. `autoexam.cls` now maps `\ifkey` to the instructor-only build (`AutoExamSolMode=only`) and forces `\ifsolutions`, so `\ifkey` implies `\ifsolutions` — an exam's answer key IS its instructor copy, and `\ShowKey`/source `\keys` request it directly. `test_mode_effects.py`'s ShowKey row pins this (asserts `\ShowKey` reveals identically to `\ShowSolutions` for a no-`\versions` fixture).
- **The autoexam/quiz question shuffle is now a typeset-time list permutation, not a source-text rewrite.** `\shuffle` used to run a pre-pass that re-read the document off disk, regex-parsed the `\begin{problems}` blocks with a hand-rolled partial-TeX tokenizer, Fisher-Yates-permuted the string fragments, and wrote a per-version temp `.tex` to `\input`. `{problems}`/`{mcproblems}` now put `\problem` into *collect* mode — each item records its args instead of typesetting, `\newpage` marks a page boundary, `\section` marks a hard shuffle boundary, `\extracredit` defers to the end — and `\end` emits the section permuted per version through the existing `pbank_problem_item` path (`pbank_emit_section` in `problem_engine.lua` + a new pure `problem_shuffle.lua`, unit-tested under `texlua` via `test_shuffle.lua`). The authoring syntax is unchanged and existing exams need no edits; a non-shuffled exam is byte-identical to before. Because draws now happen at emit time, a `\shuffle` exam's per-version orderings differ from the old scheme — a one-time reshuffle (deterministic and reproducible as before). This deletes ~170 lines of fragile string-parsing (`shuffle_problems_body` et al.), collapses the per-version body temps to one, and removes the whole class of `\newpage`-as-delimiter and misparse fragilities. The RNG is a per-version-seeded MINSTD stream with high-bit extraction + a SplitMix32 avalanche, so even small exams give every version a distinct, uniform order. Known gap: the `.sco`/`\scorepage` instructor grid still reflects authored order (only wrong under `\shuffle` + `\scorepage` + per-problem-varying points at once; uniform-point sections are correct). Also: `problem_engine.lua`/`texlib_synctex.lua` scratch now routes to a hashed system-temp subdir when neither `TEXLIB_AUX_DIR` nor `-output-directory` is set, so even a bare `lualatex doc.tex` leaves zero engine scratch (body/`.sco`/`.srcmap`/synctex) beside the source.
- **Weekly quiz-day auto-quizzes are suppressed on exam days.** When a `quiz-days` weekday lands on the same day as an `\exam` (common on a compressed summer calendar, where an exam placed on a Thursday collides with a Thursday quiz day), the schedule engine no longer stacks an automatic "Quiz N" on top of the exam — an exam and a quiz on the same day is virtually never intended. `render_grid`'s auto-quiz pass in `schedule.lua` now also skips a cell flagged as an exam day. The two explicit opt-outs are unchanged and still available for other cases: `\noquiz{<date>}` (suppress one day) and the `\exam[noquiz]` option (suppress the whole exam week). The suppression applies **only** to the automatically-generated quizzes — an explicit `\quiz[date=<exam day>]` still renders on the exam day (it is appended directly, independent of the auto pass), so a deliberately co-scheduled quiz is preserved. Existing schedules that relied on a stray exam-day auto-quiz will lose it and renumber; courses that worked around this with a hand-placed `\noquiz{<exam date>}` can drop it (still harmless if kept). Covered by `Schedule/test_schedule_quiz_exam.lua`.
- **Exam and quiz instructions are auto-wrapped in the titled "Instructions:" box — including instructions *files*.** Previously only inline/default instructions were boxed; a user-set `exam-instructions-file`/`quiz-instructions-file` rendered *unboxed* ("controls its own layout"), which forced every course instructions file to hand-roll the `\fbox{\fbox{\parbox{\dimexpr\linewidth-4\fboxsep-4\fboxrule\relax}{\large\bf Instructions:}…}}}` boilerplate itself. `autoexam.cls` and `quiz.cls` now render all three paths (file/inline/default) through a single shared `\TeXLibInstructionsTitled{<prefix>}` renderer in `texlib-instructions.sty`, so instructions files can be just their content. Quizzes gain the bold "Instructions:" header and full-width box they lacked (they previously used the centered, `\footnotesize`, fixed-6.25in `\TeXLibInstructionsBox`, which is unchanged and still used by `bingo`). A document that genuinely needs full layout control over its own instructions file can opt out with `\TeXLibInstructionsUnboxed` in its preamble (bare, no box). Exam-cover output for existing inline/default exams is byte-identical; **file-based** exam/quiz instructions now pick up the box, so any course file that hand-rolled the box must drop it to avoid a double box (Math 182's `exam-instructions.tex`, `exam-instructions-series.tex`, and `quiz-instructions.tex` were updated accordingly).

Under LuaLaTeX that pairing emits one inert *empty* `\special{}` per page during `longtable`'s trial/measuring pass; the PDF backend can't emit a non-`pdf:` special and logs "Non-PDF special ignored!" on every shipout. The cell color itself is drawn through the color stack, not that special, so the warning was cosmetic — but it fired on every schedule build. `schedule.cls` now builds the grid on `tabularray`'s `longtblr`: native `\SetCell{bg=...}` shading (no `colortbl`, so no stray special), `rowhead=1` for the header that repeats atop each page (replacing `\endhead`), `hlines` plus a trailing `\hline` after the header row for its two-line separator (the vertical rules break across the gap, matching the old `\hline\noalign{\vskip2pt}\hline`), and `rowsep=0pt` so row heights — and therefore page breaks — match the old grid. `longtblr`'s cross-page "(Continued)" head/foot are suppressed so a multi-page schedule paginates as tightly as before: `contfoot`'s `empty` template drops the foot, but `conthead`'s `empty` template is a no-op in this `tabularray` release, so its text macro `\tblrcontheadname` is blanked at `\AtBeginDocument` instead. The pypdf logic is now factored into `Sublime/texlib_pdfpost.py` and run in-process when pypdf is importable, else via a discovered external Python that has it (`_run_pdfpost` / `_external_python`, honoring `$TEXLIB_PYTHON`). `deploy.ps1` deploys and syntax-checks the new module.
- **`\begin{solution}` content now has working inverse search in Solutions-mode builds.** The originally-suspected root cause (`tcolorbox` defers shipout for internal measurement, like `xltabular` above) was wrong — disproved by ablation, stripping `tcolorbox` out of `{solution}` entirely still failed identically. Two separate bugs were actually stacked: (1) `problem_engine.lua` never staged a SyncTeX redirect for the solution region at all — `p.solution` was `tex.print`'d as a raw string with no file backing, so it silently inherited whatever `(file, line)` the stem's own redirect last left active; fixed with a new `pbank_stage_solution`/`emit_solution_block` pair that stages and `\@@input`s the solution's own bank-file lines, deferred through a follow-up `\directlua` token (`texlib_synctex.lua` allows only one pending redirect at a time — same pattern as `pbank_print_catalog`'s existing per-id deferred calls). (2) Separately, `tcolorbox`'s `enhanced` mode (needed for the old left-accent border) does its own internal box handling that defeats `synctex edit`'s reverse search even for correctly-tagged content, confirmed generic (not specific to solution content) and traced to `\unvbox` splicing nodes with no box-open record of its own — fixed by dropping `tcolorbox` from `{solution}` entirely in favor of plain `\colorbox`/`\parbox`, `\box` (not `\unvbox`) to insert the pre-collected content as a real nested box node, and a hand-drawn `\vrule` for the left accent. Trade-off: the box can no longer break across a page boundary the way the old `breakable` `tcolorbox` could; accepted after surveying every shipped solution (none exceed ~7 lines, none use diagrams/tables, no historical need for one). `Sublime/test_synctex_integration.py`'s Scenario 2 now passes outright — no more known-failure carve-out.
- **Schedule SyncTeX inverse search now actually works (was silently broken under `xltabular`).** The v0.2.0 claim that "clicking a calendar cell opens `template.tex` at the directive's line" held only against a hand-fabricated `.synctex.gz`, never a real build: `xltabular` (via `longtable`) defers box shipout to its output routine, by which point every cell's raw SyncTeX line has collapsed to the grid file's last line, so the `.schedmap` rewrite found nothing to remap. Two-part resolution: (1) `_rewrite_synctex_for_schedmap` now only repoints the grid-file `Input` record at the real source when at least one cell record was actually remapped — otherwise it honestly leaves clicks landing in the auto-generated grid scratch file instead of confidently pointing at a wrong source line; (2) the new opt-in `box-grid` renderer (above) makes per-cell attribution genuinely correct. Under the default `xltabular` renderer, inverse search remains the honest grid-file fallback.

### Removed

- **The "All Versions" / "All Versions (Solutions)" Sublime build modes, and the standalone `build_versions.py` parallel multi-version builder.** Both are superseded by the automatic per-version/solutions PDF slicing above — a normal default build now does what these did, faster (one compile instead of one recompile per version, even parallelized across cores) and without extra clicks. Removed `Sublime/texlib_builder.py`'s `MODE_ALLVERSIONS`/`MODE_ALLVERSIONS_SOLUTIONS` dispatch and the now-dead `_build_version`/`_make_version_source_copy`/`_cleanup_version_scratch`/`_parse_versions` helpers, the matching `TeXLib.sublime-build` variants, `build_versions.py`, and `test_build_versions.py`. ### Limitations (schedule SyncTeX)

- **Multi-week clustering under one source line.** Weeks without an explicit directive inherit the most recent directive's line via fallback propagation, so several consecutive weeks may share one attribution (e.g. all weeks between two `\holiday` calls map to the earlier one).   checks that key generated artifacts are non-empty (`EXPECT_ARTIFACT_NONEMPTY`
  — e.g. the schedule's `*_schedule_grid.tex`). This catches the "compiles green
  but renders blank/garbled" class a build-only check misses — the empty
  schedule grid is now a hard failure. Opt-in `--visual` pixel-diffs each page
  of the deterministic modules (`VISUAL_MODULES`: Schedule, Report Cards,
  Syllabi, Notes) against committed references in `tests/visual_refs/`
  (`--update-refs` to regenerate), catching layout regressions like the
  row-stub that text checks can't see. New flags: `--no-content`, `--visual`,
  `--update-refs`, `--dump-text`. Every external-tool check (poppler /
  ImageMagick) soft-skips when its tool is absent, so a bare TeX install still
  runs build-only. CI (`smoke.yml`) installs `poppler-utils` so content checks
  run on every push; visual regression stays a local aid (its references are
  rendering-environment-specific). Builds now run multiple passes — re-running
  while the `.log` requests it (latexmk-style) — so `\pageref{LastPage}` and
  other cross-references resolve in the rendered output ("1 of 2" rather than
  the one-shot "1 of ??").
- **`recitation-days` meta key on the `schedule` class.** Now registered in the
  `meta` family (mirroring `quiz-days`: a `\clist_gset` store + an expandable
  `\GetRecitationDays`), so `\meta{recitation-days = R}` adds a capacity-0
  recitation column. Previously `\GetRecitationDays` was an empty
  `\providecommand` with no key to set it, despite the README documenting one —
  `\meta{recitation-days=...}` errored with "unknown key".
- **`month-pages` meta key on the `schedule` class.** `\meta{month-pages = true}` typesets each calendar month as its own table on its own page (`\newpage` between months) instead of one continuous term-long table. A week straddling a month boundary is repeated — at the foot of the earlier month and the head of the next — so every month shows complete weeks, wall-calendar style; week numbers stay continuous across the term. Default (`false`/omitted) is unchanged. Implemented as a page-group partition in `render_grid` (one group = whole term by default, one group per month when enabled), with the table header/lastfoot boilerplate re-emitted per group.
- **Per-call variable overrides on `\problem`.** Inside `\begin{problems}…\end{problems}`, `\problem{id}` accepts a trailing optional argument that pins random variables to specific values for that one instance: `\problem{quadratic}[a=1, b=2, c=3]` solves `x²+2x+3` instead of a freshly-sampled quadratic. Partial fixes work too — `\problem{quadratic}[a=1]` leaves `b` and `c` random. The engine adds a `fixed[]` table that `set_var`/`set_rng`/`calc_var`/`pick_*` consult before writing, so a bank entry's own randomisation calls become no-ops on locked names. `push_scope`/`pop_scope` save and restore the table around each problem, so the override is local. `\importproblem` was upgraded to use the same lock semantics.
- **`texlib-problembank.sty`** — single source of truth for the shared problem-bank LaTeX glue: engine loader, `\setvar`/`\setrng`/`\calcvar`/`\get`, the four `\pick*` commands, `\getlist`/`\geti`/`\foreachpick`, the `\begin{problem}` environment, `\getproblem` (+ `\useproblem`/`\reqproblem`), `\ppart`, `\@problem@item`, `\loadbank`, `\importproblem`, and `\providecommand` defaults for `\workbox`/`\autoexam@problem@sep`. Required by `autoexam.cls` and `quiz.cls`; collapses ~120 lines of duplicated code per class to a single `\RequirePackage`.
- **`texlib-corepkg.sty`** — universal package bundle: fontenc/lmodern/geometry, expl3/xparse/ifthen/etoolbox, xcolor, the amsmath family, `texlib-mathutils`, graphicx, tikz/pgfplots + standard libraries, and hyperref with the canonical `\hypersetup` used across every TeXLib class. `basic-utilities.sty` now `\RequirePackage`s this and adds its own extras (siunitx, caption, tasks). `autoexam.cls`/`quiz.cls` load it directly; `didactic.cls`/`pset.cls`/`report-card.cls` inherit it transitively via basic-utilities. Each of the heavier classes shrank by 8–11 lines.
- **`texlib-itemfmt.sty`** — `\encircle` (the circled-token decoration) and `\extracredit` (extra-credit `\question` variant), previously duplicated across `autoexam.cls` and `quiz.cls`. `\extracredit` is now available to autoexam too.
- **`texlib-pagestyle.sty`** — `\SetTeXLibExamRules` bundles `\pagestyle{headandfoot}` + `\firstpagefootrule` + `\runningheadrule` + `\runningfootrule`. Sibling to `texlib-footer.sty` (which serves the fancyhdr-based classes the same way).
- **`texlib-thmenv.sty`** — the union of `\newtheorem*` declarations from `autoexam.cls` (3) and `quiz.cls` (14): `thm*`, `defn*`, `cor*`, `prop*`, `lem*`, `conj*`, `ques*`, `prob*`, `exam*`, `ex*` (legacy short alias), `notn*`, plus the remark-style `rmk*`/`recall*`/`case*`/`desiderata*`. Both classes inherit the full set.
- **Shared `\the*` aliases in `course-metadata.sty`.** `\theCourseSubject`, `\theCourseNumber`, `\theCourseTitle`, `\theCourseSection`, `\theCourseRoom`, `\theCourse`, `\theInstructor`, `\theInstitution`, `\theSchool`, `\theSeason`, `\theYear`, `\theTerm` are all `\providecommand`s here now, so no class needs to declare them and there's no risk of a `\newcommand` clash if a future metadata key reuses one of those names. Class-specific aliases (`\theExamNumber`, `\theQuizNumber`, …) stay in their respective classes.
- **`tests/fixtures/Exams/fix-test.tex` + `fix-bank.tex`** — exercises the new `\problem[fix]` syntax. Registered as a smoke-test entry so the feature is covered on every CI run.
- **`smoke_test.py` now collects `.cls` files from module subdirectories** when assembling each build's temp dir, so test entries under `tests/fixtures/<Module>/` can use a sibling module's class.

### Changed

- **Test assets consolidated under `tests/`.** The top-level `Test/` directory is gone — its feature fixtures moved to `tests/fixtures/Exams/` and `tests/fixtures/Metadata/` (joining `tests/scenarios/` and `tests/visual_refs/`), removing the confusing `Test/` vs `tests/` case clash and the empty per-module scaffolding dirs. `MODULES`/`EXPECT_TEXT` in `smoke_test.py` were repointed accordingly; the fixtures still build on every push.
- **`examples/Math181-Fall2026` expanded into a full course folder and wired into CI.** Added `syllabus.tex`, `schedule.tex`, and a multi-version `exam-01.tex` + `bank.tex` (`\versions{A,B,C}` + `\shufflepages`) alongside the existing lecture and quiz — all five documents share one `coursemeta.tex` and are now registered as build-only smoke fixtures, so the documented end-to-end workflow can no longer silently rot when a class changes. `smoke_test.py` gained a `CLASS_HOME_MODULE` map (+ `detect_class`): a build whose source lives outside its document class's home module (e.g. an `examples/` `{quiz}`/`{schedule}` doc) now gets that module's default includes (`quiz-instructions.tex`, the schedule `.lua` helpers) copied into the build dir — the comma-path-safe way, since the recursive `TEXINPUTS` fallback can't reach them under a comma-bearing root.
- **The `schedule` environment no longer emits the title banner itself.** `\maketitle`/`\scheduletitle` must now be called explicitly in the document body (canonically right after `\begin{document}`, before `\begin{schedule}`), matching every other TeXLib class. This lets a schedule run title-less (e.g. when the banner lives elsewhere) by simply omitting the call. Existing schedule documents need one added `\maketitle` line; the canonical `Schedule/template.tex` and the README tutorial were updated accordingly.
- **`autoexam_engine.lua` → `problem_engine.lua`.** The file is shared between `autoexam` and `quiz`; the old name implied otherwise.
- **Lua engine function names: the shared ones gained a `pbank_*` prefix.** `pbank_problem_item`, `pbank_apply_fix`, `pbank_set_bankfile`, `pbank_inject_part`, `pbank_first_on_page`, `pbank_part_*`, `pbank_stretch_list`, `pbank_pending_*`, and the new `pbank_suppress_redirect` flag. Autoexam-specific functions kept their `autoexam_*` prefix (`autoexam_run_versions`, `autoexam_versions`, `autoexam_shuffle_pages`, `autoexam_write_srcmap`, `autoexam_read_body`, `autoexam_scorepage`, `autoexam_gradingrow`) — they would only ever be called by autoexam.cls.
- **`\loadbank` is now defined once in `texlib-problembank.sty`.** It activates the SyncTeX bank-file redirect via `pbank_set_bankfile()` so inverse search from the PDF lands in the bank source file (previously: only quizzes called this; autoexam ran with the redirect dormant to avoid a multi-version input-stack overflow).
- **The bank SyncTeX redirect now writes ONE reused scratch file per job** (`<jobname>_synctex.tex`) instead of one `<jobname>_synctex_<id>.tex` per problem. SyncTeX records the bank path, never the scratch file, and redirects are served strictly sequentially (each `\@@input` read to EOF and closed before the next is staged), so a single overwritten file is safe and course folders no longer accumulate one orphan `.tex` per problem.
- **Inline-defined problems now get inverse search into the document.** A `\begin{problem}{id}...\end{problem}` written directly in an exam/quiz with no `\loadbank` is attributed (via `status.filename`) to the file it lives in, so double-clicking it in the PDF jumps to its `\begin{problem}` block in that source — line-accurate, through the same single reused scratch file, no per-problem `_prob_` temp. Works in single- and multi-version builds for problems defined in the preamble or (single-version) body; problems in a multi-version body-replay file still use the per-problem fallback. `\loadbank` now restores the previous bank context after `\input` (stack-based, nesting-safe) so a `\begin{problem}` placed *after* a `\loadbank` is attributed to the document, not the stale bank file.
- **Quiz default instructions now support SyncTeX inverse search.** The boxed default wording moved out of `quiz.cls` into a real `Quizzes/quiz-instructions.tex` that the class `\input`s (boxed) when a quiz sets neither `quiz-instructions-file` nor an inline `quiz-instructions` — so double-clicking the instructions in the PDF jumps to that source, mirroring autoexam's `autoexam-instructions.tex`. Edit `quiz-instructions.tex` to change the default for every quiz. (Per-quiz overrides are unchanged: `quiz-instructions-file=` is unboxed/full-control; `quiz-instructions={…}` is inline.)
- **`quiz-instructions-file` can now be set course-wide in `coursemeta.tex`.** It's now a course-metadata key (defined in `course-metadata.sty` alongside `bank-path`), so `\metasetup{ quiz-instructions-file = my-quiz-instructions }` in `coursemeta.tex` points every quiz in the course at one local instructions file — resolved relative to the coursemeta directory (`\GetCourseMetaDir`), so it's found from any quiz folder regardless of depth. Resolution mirrors `bank-path`: tried as-is first (per-quiz, document-relative), then coursemeta-relative. Still overridable per quiz via `\meta{ quiz-instructions-file = … }`, and unset → the shared default `quiz-instructions.tex`. Defining the key in `course-metadata.sty` rather than `quiz.cls` is deliberate: `coursemeta.tex` is read before the class body, so a quiz-only key would be missed (and would clash with the metadata engine's unknown-key handler). Exams and other classes that load `coursemeta.tex` simply ignore the key. Covered by a new smoke-test scenario (`tests/scenarios/quiz/coursemeta-instructions/`).
- **Smoke-test scenarios can now make text assertions (`expect-text`).** A scenario that ships an `expect-text` file (PDF substrings, one per line) asserts rendered content directly and — when it carries no reference PNGs — skips the pixel diff, so a feature about *which text renders* (not layout) needs no committed image ref. Scenarios may also ship their own `coursemeta.tex` to exercise course-metadata keys. First user: the `quiz/coursemeta-instructions` pack.
- **Builds now leave a single inverse-search file: `<base>.synctex`.** The Sublime builder's post-process (`_finalize_synctex`) decompresses lualatex's `<base>.synctex.gz` to a plain `<base>.synctex` and deletes the `.gz`; because a viewer reads an uncompressed `.synctex` directly, SumatraPDF no longer spawns its `<base>.synctex.gz.sum.synctex` decompression cache. The build-time SyncTeX scratch `<base>_synctex.tex` (and any legacy per-problem `<base>_synctex_<id>.tex`) is removed too. Net: one hidden `.synctex` per document instead of up to three files. The schedule `.schedmap` → SyncTeX rewrite is unaffected — it runs on the `.gz` before decompression. (Raw command-line builds outside the Sublime builder still produce the `.gz` + scratch; only the builder finalizes.)
- **Multi-version exams now use the bank redirect too.** `autoexam_run_versions` no longer sets `pbank_suppress_redirect=true`. The flag existed to dodge a LuaTeX input-stack overflow when the version loop re-inputs every problem, but the `texlib_synctex.lua` helper closes each `\@@input` at EOF so the inputs pop and stack depth never accumulates (verified: a 3-version exam — 36 bank inputs — builds cleanly even with `max_in_open` forced to 20). Result: multi-version inverse search lands in the bank (not per-problem `_prob_` temp files), and these builds also produce just the single reused scratch file. The flag is retained as an explicit per-call override.

### Removed

- **`\newproblem` and `\dupproblem` are gone — define problems with the `\begin{problem}` environment.** The environment does everything the commands did (define in a bank file, the preamble, or the body) plus supports SyncTeX inverse search, so there's now one canonical way to author a problem. No live document used the commands. Migration is mechanical: `\newproblem{id}{meta}{body}[ans]` → `\begin{problem}{id}[meta]` *body* `\solution` *ans* `\end{problem}`. The dead `define_problem()` Lua backend was removed too (`define_problem_from_env()` remains).

### Fixed

- **`texlib-problembank` no longer forces every loading document onto LuaLaTeX.**
  Its load-time engine loader ran `\directlua` unconditionally, so any
  non-LuaTeX (pdflatex) class that `\RequirePackage`s it — e.g. `didactic`,
  which auto-loads it so lecture notes can optionally `\getproblem` — died at
  load with "Undefined control sequence `\directlua`". The loader is now guarded
  by `\ifdefined\directlua`: under LuaLaTeX it loads as before; under any other
  engine the load is skipped and the bank macros route through an internal
  `\pbank@lua` bridge that raises a clear "Problem-bank features require
  LuaLaTeX" error — but only if a bank command is actually used, so notes/handout
  documents that merely load the package still compile under pdflatex. The
  `\directlua` primitive itself is left untouched (not shadowed), so other
  packages' `\ifdefined\directlua` engine probes still work.
- **Schedule grid no longer leaves a vertical-rule stub below the last row.** The table's bottom edge used to show a short fragment of the `WEEK`/day column rules hanging beneath the final week — longtable was synthesising a phantom trailing row from the non-empty `\endlastfoot` (`\noalign{\vskip -12pt}\hline`). `render_grid` now ends every row, including the last, with `\tabularnewline \hline` and uses an empty `\endlastfoot`, so the last row's own rule is the clean bottom edge. (The same fix applies to each month's table in `month-pages` mode.)
- **SyncTeX bank-file redirect no longer fires "missing \item" errors for problems past line ~1000.** The redirect path pads its temp file with blank lines so the served content lines up with the bank's true source lines (for accurate inverse-search attribution). Each blank line was tokenising — under the default `\endlinechar=13` — to a `\par` token; exam.cls's `\trivlist` starts complaining once roughly 1000 `\par`s have stacked inside a `\question` item, breaking single-version exams and quizzes whenever a problem lived past line ~1000 of the bank. `typeset_problem` now brackets the padding region with `\endlinechar=-1\relax` on line 1 and `\endlinechar=13\relax` on `sm.line-1`, so the blank lines emit zero tokens (no `\par`) and only one harmless `\par` fires right before the real content begins. SyncTeX line attribution is preserved — clicks still land on the correct bank line.
- **`\importproblem` overrides are now actually locked.** Previously its overrides were set via direct `set_var` calls, which the imported file's own `\setrng` could clobber. It now routes through `pbank_apply_fix` and gets the same `fixed[]`-table semantics as `\problem[a=1,b=2]`.

### Cleanup

- Stripped duplicate `\RequirePackage` lines (`fontenc`, `lmodern`, `geometry`, `xparse`, `expl3`, `etoolbox`, the amsmath family, `graphicx`, `tikz`/`pgfplots`, `hyperref` + `\hypersetup`) from `didactic.cls`, `pset.cls`, and `report-card.cls` — all now come through `basic-utilities` → `texlib-corepkg`.
- Removed stray build artifacts (`Notes/template.aux`/`.log`/`.out`/`.toc`, `Problem Sets/template.pdf`/`.synctex.gz`) that had escaped `.gitignore`.

## [0.1.1] — 2026-05-23

Patch release: aux-directory routing for the Sublime builder + theorem-environment polish across the document classes.

### Added

- **Starred (unnumbered) theorem environments in `didactic` and `pset`.** Every theorem-family environment gets a `*` twin (`theorem*`, `lemma*`, `definition*`, `proposition*`, `corollary*`, etc.) plus, in didactic, the short-alias starred forms (`defn*`, `conv*`, `ques*`, `exer*`, `exam*`, `notn*`, `chal*`). Same tcolorbox styling as the numbered versions; consume no counter. Use for one-off results you don't want to clutter the numbering with.
- **Context-sensitive top-level `enumerate` labels in `didactic`.** Inside bold-titled theorem/definition environments, top-level enumerate items render as bold roman (`i.`, `ii.`, `iii.`); everywhere else (body text, remark/question/recall boxes), they render as italic roman. Implemented via `\AtBeginEnvironment` raising a boolean that's read at label-typesetting time, so a bare `\begin{enumerate}` adapts to its surroundings with no per-list configuration.
- **Bold roman top-level `enumerate` labels in `pset` and `autoexam`.** Matches didactic's bold-roman-in-theorem-environment look, applied unconditionally since neither class has a mixed-context need. `\ref` to enumerate items prints `i`, `ii`, ... consistent with the visible label.
- **`didactic` auto-sets the section counter to `\GetUnitNumber` in `\maketitle`.** Subsections now render as `N.1`, `N.2`, ...  and section-numbered theorems pick up the unit prefix without the per-file `\setcounter{section}{...}` boilerplate. Guarded against documents that omit the unit-number metadata key.

### Fixed

- **`Sublime/texlib_builder.py` now honors the LaTeXTools `aux_directory` setting** (the template ships with `"<<temp>>"`, which was previously ignored). The builder routes the engine via `-output-directory` to a stable per-document temp dir under `%TEMP%\texlib-aux\<hash>\`, then copies the PDF, `.synctex.gz`, and any `.spl` signal back next to the source. Net effect: `.aux/.log/.out/.toc/.bcf/.bbl/.fls/.fdb_latexmk` stop accumulating in source directories and OneDrive doesn't see them as changes on every Ctrl+B. biber invocations now use `--input-directory` / `--output-directory` so biblatex cross-references still resolve when aux routing is active. Set `aux_directory` to `""` or `"<<root>>"` in `LaTeXTools.sublime-settings` to opt out and restore the old in-source behavior.

## [0.1.0] — 2026-05-22

Initial public-on-GitHub release. Snapshot of TeXLib after the documentation pass and CI wiring.

### Added

- **Core packages.** `basic-utilities.sty`, `course-metadata.sty` (v8.1 layered metadata engine), `texlib-build.sty` (unified build flags), `texlib-footer.sty`, `texlib-mathutils.sty`, `texlib-theorems.sty`. `quiver.sty` vendored from https://q.uiver.app.
- **Document-class modules.** `bingo`, `autoexam` and `quiz` (which share `problem_engine.lua` for problem-bank randomisation), `didactic` (lecture notes), `pset` (problem sets), `report-card`, `schedule` (with `date.lua` / `calendar.lua` / `schedule.lua`), `syllabus`. Each module ships with a `.cls`, a `template.tex`, and a `README.md`.
- **Smoke-test harness.** [`smoke_test.py`](smoke_test.py) builds every module's `template.tex` and reports pass/fail. Supports `--modes all` to also build with `\StudentMode`, `\ShowKey`, `\ShowSolutions`.
- **Sublime Text integration.** Custom builder `texlib_builder.py` plus build system, command-palette entries, and LaTeXTools settings. See [`Sublime/README.md`](Sublime/README.md).
- **GitHub Actions CI.** `.github/workflows/smoke.yml` runs `smoke_test.py` on every push and PR inside a TeX Live full container; uploads `.log` files as artifacts on failure.
- **Quickstart documentation.** New per-machine and per-course setup walkthroughs in the README, plus [`coursemeta.example.tex`](coursemeta.example.tex) as a copy-paste starting point.
- **MIT license** (with a carve-out noting `quiver.sty` is third-party).
